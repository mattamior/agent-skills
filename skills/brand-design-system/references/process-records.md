# Process Record Guidance

Read this reference for new identity work, historical reconstruction, or a reusable handoff. The goal is traceability, not paperwork: preserve the decisions and evidence another person or agent would need to understand, reproduce, or safely extend the brand.

## Separate evidence from reconstruction

Classify each material statement as one of:

- **Evidence:** directly supported by a file, commit, message, dated approval, rendered output, or other inspectable source.
- **Inference:** a reasonable interpretation derived from evidence; record the supporting source and label the conclusion.
- **Unknown:** not established by available material. Do not fill the gap with a plausible narrative.

For an existing brand, inspect source artwork, asset documentation, version history, implemented metadata, and reachable design records. A final asset pack can establish what was approved and delivered, but not necessarily how rejected directions evolved.

## Maintain two records

Use the templates only when the project has no equivalent records:

- [Brand process log](../assets/templates/brand-process-log.md): brief, evidence register, explored directions, decisions, approvals, and open questions.
- [Brand handoff](../assets/templates/brand-handoff.md): approved master, invariants, asset inventory, implementation state, QA evidence, and limitations.

Store records in the project's existing documentation location. If no convention exists, keep them beside the brand source files or in a clearly named brand documentation directory. Do not copy the templates into a project unless the brand task authorizes creating durable project artifacts.

## Record decisions at checkpoints

Update the process log when a choice materially narrows or changes the identity:

- brief or audience approval;
- concept direction selection or rejection;
- palette, type, geometry, negative-space, or lockup approval;
- production master freeze;
- asset-pack acceptance;
- implementation and visual acceptance.

Capture the date, decision maker when known, evidence location, decision, and short rationale. Do not claim approval from silence, a generated preview, or an unverified implementation.

## Preserve source relationships

The handoff should identify the editable master and explain how derivatives were produced. Keep concept images, production sources, exported assets, and implementation files distinct. Record font names and licensing constraints without embedding unlicensed font files.

When a repository is available, include stable paths and relevant commits or tags. For external design tools, record the document or frame identifier only when it is safe and accessible to the intended maintainers.
