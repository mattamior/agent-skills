# Brand Design System

Create a brand identity that remains faithful from the chosen design through production assets. Treat the approved artwork—not a verbal recollection—as the single source of truth.

## Start with intent

Establish the product or organization name, audience, use cases, required languages, visual constraints, target markets, and whether the request is for exploration, refinement, production assets, or web integration. Inspect existing assets and implementation before asking questions that can be answered from them.

For new identity exploration, create a small set of materially distinct, vector-friendly directions. Explain the visual idea and likely category associations. A similarity review can flag visual or naming risk, but is not legal clearance; do not represent it as trademark advice.

## Lock the approved master

Once the user selects a direction, record the visible invariants: exact geometry and proportions, palette, stroke behavior, wordmark casing and typography, backgrounds, negative space, and lockup relationships. Do not silently simplify, redraw, reinterpret, or substitute those decisions while producing derivatives.

Use editable SVG or another vector-native format for production logo work. Use image generation only for exploration or where a raster deliverable is actually requested. Pathify a final wordmark when portability matters and licensing permits it.

## Produce only what the delivery needs

Read [production asset guidance](references/production-assets.md) when producing production assets, application icons, social images, or a web-ready pack. Generate the minimum useful set rather than an indiscriminate export matrix.

When the user authorizes web integration, inspect the project and follow existing asset conventions. Update only the approved branding surface and required metadata; do not alter product behavior or information architecture.

## Verify visible output

Read [visual QA guidance](references/visual-qa.md) whenever finalizing production assets or reviewing an implementation. Validate rendered output, not just SVG source. In particular, verify transparency, color application, small-size readability, lockup proportions, and actual favicon/manifest delivery.

Keep concept previews separate from production assets. Report what was generated, what was integrated, validation evidence, and known limits such as legal clearance or an unavailable browser check.
